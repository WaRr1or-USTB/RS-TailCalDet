# RS-TailCalDet 团队协作与实验交付指南

本文面向项目组成员，说明仓库、数据与模型资产的获取方式，以及后续实验的统一边界。具体运行命令可由成员根据各自报告任务，结合仓库 README、脚本帮助和开发 Agent 生成。

## 1. 仓库访问

项目仓库为 GitHub 私有仓库 `RS-TailCalDet`。负责人在仓库 `Settings → Collaborators` 中邀请成员；成员接受邀请后，可通过 GitHub Desktop 或 Git 命令行克隆仓库。

仓库包含：

- 训练、阈值校准、超大幅面滑窗评测与绘图代码；
- 固定的 60%/10%/30% 数据划分清单；
- 最终模型与阈值文件；
- 已锁定的评测结果及报告用图表；
- 项目说明和实验复现入口。

最终模型由 Git LFS 管理。克隆后应确认以下文件不是 LFS 指针：

## 2. 团队 Release 资产

原始与派生数据不直接提交到 Git 历史。负责人应在私有仓库中建立新的团队资产 Release，例如：

```text
Team Assets s2026 v2
```

建议包含以下资产：

| 资产 | 用途 |
|---|---|
| `RS-TailCalDet_data_v2_full_s2026_v2.tar.gz` | 完整训练数据，供训练、消融和复现实验使用 |
| `yolo26x_s2026.pt` | 从零开始训练 YOLO26x 时使用的初始化权重 |
| `SHA256SUMS.txt` | 所有 Release 资产的完整性校验值 |
| `ASSET_MANIFEST.md` | 资产版本、样本数量、来源与使用范围 |

完整数据包应从当前训练服务器的项目目录导出：

```text
/root/autodl-tmp/TZB2026_RS-CalYOLO26x/data_v2
```

数据包至少应覆盖划分清单中的全部资产：

- 官方样本：4481 张；
- 外部公开舰船样本：156 张，仅进入训练集；
- 派生增强样本：180 张，其中 132 张可用于训练，48 张按清单标记为排除项；
- `report_split_v16` 下的固定划分清单、数据配置和统计摘要。

当前本地仓库只有 4481 张官方样本的副本，缺少上述 156 张外部样本和 180 张派生样本。因此应以训练服务器上的完整 `data_v2` 为准，打包后通过 MobaXterm 下载到本地，再上传到新的私有 Release。不要用新资产覆盖旧资产；保留旧 Release，并用 `v2` 标识修订版本。

`yolo26x_s2026.pt` 的已知信息：

```text
size: 118667365 bytes
sha256: 9fdd44a31c504547ffb81d2c6d9e6dac3493c8eaa8b0398d3f43bae6c7003e92
```

竞赛数据和派生数据只在私有仓库成员之间分发，不公开发布。上传前还应确认单个 Release 文件满足 GitHub 的文件大小限制；若完整数据包超限，应按“数据主体 / 外部样本 / 派生样本”拆分，并在 `ASSET_MANIFEST.md` 中记录组合关系。

## 3. 固定数据协议

所有报告实验统一使用以下文件，不得自行重新随机划分：

```text
data_v2/report_split_v16/assignments.csv
data_v2/report_split_v16/dataset_report.yaml
data_v2/report_split_v16/split_summary.json
```

官方样本固定划分为：

- 训练集：2688 张，约 60%；
- 校准集：448 张，约 10%；
- 锁定验证集：1345 张，约 30%。

外部样本和训练派生样本只允许进入训练阶段。校准集只用于类别阈值选择；30% 锁定验证集只用于最终评测，不得参与训练、早停、阈值选择或实验筛选。

## 4. 已提供的关键代码

成员应优先复用仓库现有入口，避免重新实现评分逻辑：

| 文件 | 作用 |
|---|---|
| `scripts/prepare_report_ablation_datasets.py` | 根据固定划分生成不同数据条件的消融配置 |
| `scripts/train_yolo_baseline.py` | 统一训练入口 |
| `scripts/optimize_class_thresholds.py` | 在 10% 校准集上选择类别阈值 |
| `scripts/run_report_evaluation.sh` | 在三个固定大图验证子集上执行锁定评测 |
| `scripts/evaluate_big_images_sliding.py` | 超大幅面滑窗推理与 V1.6 指标计算 |
| `scripts/generate_dataset_report_figures.py` | 生成数据统计与报告图表 |
| `tests/test_v16_scoring.py` | 评分口径单元测试 |

最终提交链路和环境说明以仓库根目录 `README.md` 为准。

## 5. 后续实验方向

各成员可根据自己负责的报告章节，让开发 Agent 阅读仓库后生成对应操作步骤。建议优先完成以下互斥、可比较的实验：

### A0：官方数据基线

仅使用固定 60% 官方训练样本，作为所有数据增强与外部数据实验的共同基线。

### A1：外部公开数据增益

在 A0 基础上加入 156 张外部公开舰船样本，用于量化公开舰船数据对舰船大类和细分类别的影响。

### A2：完整数据策略

在 A1 基础上加入 132 张训练派生样本，用于量化尾部类别定向增强的收益与代价。

### B：训练策略消融

围绕分阶段训练、低学习率微调、早停策略和随机种子开展控制变量实验。除目标变量外，数据划分、模型规模、图像尺寸和评测协议保持一致。

### C：推理与校准消融

比较统一阈值与类别阈值、不同召回约束、滑窗参数和全图逐类 NMS 设置。所有阈值只能在 10% 校准集上确定。

### D：结果分析与可视化

基于统一输出生成训练曲线、类别长尾分布、总体与分大类指标、阈值校准曲线、定性检测结果和典型错误案例。图表数据必须能够追溯到对应模型、阈值和评测目录。

## 6. 统一评价边界

所有实验必须使用比赛 V1.6 口径：

- 召回率约束按当前评分实现执行；
- 虚警率 FDR 的正式约束为不高于 20%；
- 大类与细分类别指标不得混用；
- 大类指标、25 类严格匹配指标和 V1.6 类别宏平均结果应分别保存；
- 每张超大幅面影像的推理时间应单独记录；
- 缺失类别应标记为不完整或不可计算，不得擅自记为零后参与宏平均。

## 7. 每项实验的最小回传内容

每位成员不需要回传整套服务器目录，只需提交以下可审计材料：

- 实验名称、负责人和对应报告问题；
- 使用的数据条件、模型初始化权重和关键超参数；
- 代码提交号或分支名；
- `args.yaml`、`results.csv` 和最佳模型 SHA256；
- 校准阈值文件及其 SHA256；
- 三个固定验证子集的 `protocol_metrics.json`、`summary.json` 和必要 CSV；
- 报告采用的表格、图片及其数据来源说明；
- 与 A0 基线的同口径差值，以及是否满足 V1.6 约束。

模型权重和大型中间文件不直接提交到普通 Git 历史。确需团队共享时，使用 Git LFS 或新的私有 Release 资产。

## 8. 协作原则

- 每项实验使用独立分支、独立输出目录和唯一实验名；
- 不修改固定划分清单和锁定验证标签；
- 不覆盖他人的模型、阈值或结果目录；
- 先提交实验配置和结果摘要，再由负责人决定是否合并；
- 报告中的每个数字和图表都应能追溯到模型哈希、阈值哈希和评测结果文件。

成员拿到仓库与完整 Release 资产后，即可根据自己负责的章节，让开发 Agent 读取本指南、根目录 `README.md` 和相关脚本，生成该任务所需的具体训练、评测或绘图步骤。
