# RS-TailCalDet团队下载与环境准备指南

本文说明如何接受GitHub私有仓库邀请、下载RS-TailCalDet项目以及核验模型文件。

## 1. 接受仓库邀请

项目负责人发送邀请后，GitHub会通过站内通知或账号绑定邮箱发送邀请。

1. 登录被邀请的GitHub账号。
2. 打开邀请邮件或GitHub通知。
3. 点击`View invitation`。
4. 点击`Accept invitation`。
5. 接受后确认能够访问私有仓库`RS-TailCalDet`。

如果无法看到仓库，请确认当前登录账号与负责人邀请的账号一致。

## 2. 使用GitHub Desktop下载

### 2.1 安装并登录

1. 安装GitHub Desktop。
2. 使用已接受邀请的GitHub账号登录。
3. 打开GitHub Desktop。

### 2.2 克隆仓库

1. 选择`File → Clone Repository`。
2. 在`GitHub.com`列表中选择`RS-TailCalDet`。
3. 在`Local Path`中选择本地保存位置。
4. 点击`Clone`。
5. 等待代码和Git LFS模型下载完成。

建议使用不含特殊符号且空间充足的本地目录，例如：

```text
D:\Projects\RS-TailCalDet
```

## 3. 使用命令行下载

已安装Git和Git LFS时，可以直接执行：

```bash
git clone <RS-TailCalDet仓库地址>
cd RS-TailCalDet

git lfs install
git lfs pull
```

仓库地址可在GitHub仓库页面点击`Code`后复制。

## 4. 核验模型文件

最终模型由Git LFS管理。下载完成后，模型路径应为：

```text
runs/detect/yolo26x_report60_cal10_e120_s2026_b6/weights/best.pt
```

文件大小约为113 MiB。如果文件只有几KB，说明只下载了Git LFS指针，应在项目根目录重新执行：

```bash
git lfs pull
```

Linux服务器核验命令：

```bash
sha256sum \
  runs/detect/yolo26x_report60_cal10_e120_s2026_b6/weights/best.pt \
  runs/detect/report_phase1_thresholds_r925_s2026/class_thresholds.json
```

Windows PowerShell核验命令：

```powershell
Get-FileHash -Algorithm SHA256 `
  runs/detect/yolo26x_report60_cal10_e120_s2026_b6/weights/best.pt, `
  runs/detect/report_phase1_thresholds_r925_s2026/class_thresholds.json
```

正确SHA-256：

```text
best.pt
72f7fbe5d531faa9a0a6e21b869b2c54a4d0de512b347b0e8259ca13e4e2ddd8

class_thresholds.json
b9122b09266b0f5d9c88c9866670e76cd28949f978bdff5f21b28f3202c55d49
```

## 5. 原始数据说明

Git仓库不包含完整竞赛图像和标签。仓库内仅保存数据划分协议：

```text
data_v2/report_split_v16/dataset_report.yaml
data_v2/report_split_v16/split_summary.json
data_v2/report_split_v16/assignments.csv
```

需要重新训练或开展消融实验的成员，必须通过团队内部存储单独获取完整`data_v2`目录，并将其放在项目根目录下：

```text
RS-TailCalDet/
├── data_v2/
├── scripts/
├── runs/
└── README.md
```

不得将竞赛原始数据上传至公开仓库。

取得完整数据后，需要在自己的项目路径下重新生成同一数据划分清单。脚本使用固定seed=2026，并保持60%训练、10%校准、30%锁定验证的场景级划分：

```bash
python scripts/build_report_split.py \
  --data-root data_v2 \
  --output-dir data_v2/report_split_v16 \
  --seed 2026 \
  --overwrite
```

完成后应看到：

```text
REPORT_SPLIT=PASSED
```

重新生成以下本机路径清单后，才能开始训练：

```text
data_v2/report_split_v16/train.txt
data_v2/report_split_v16/calibration.txt
data_v2/report_split_v16/validation.txt
```

## 6. 服务器环境初始化

AutoDL服务器使用以下环境：

```bash
cd /root/autodl-tmp/RS-TailCalDet
source /root/miniconda3/etc/profile.d/conda.sh
conda activate torch_env

export OMP_NUM_THREADS=8
export PYTHONPATH="$PWD/ultralytics-main"
export YOLO_CONFIG_DIR="$PWD/.ultralytics_config"
```

如果服务器仍使用历史目录名，则进入：

```bash
cd /root/autodl-tmp/TZB2026_RS-CalYOLO26x
```

## 8. 后续更新

使用GitHub Desktop时，点击`Fetch origin`，发现更新后点击`Pull origin`。

命令行方式：

```bash
git pull
git lfs pull
```

开展个人实验前应建立独立分支，不要直接修改`main`：

```bash
git switch -c ablation/<实验名称>
```

每次实验必须使用新的运行名称，禁止覆盖正式模型和锁定评测目录。
